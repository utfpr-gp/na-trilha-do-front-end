O cartão da trilha ganha uma página em volta: um cabeçalho com o nome do Trilheiro, uma seção "Trilhas em destaque" e um rodapé. E ganha também o primeiro arquivo de CSS próprio, que deixa o título do cartão verde-mata, por cima da cor que vem do Bootstrap.

Parece pouco, mas é aqui que muita gente tropeça: a regra está certa, o arquivo está ligado, e a cor não muda. Este capítulo revisa, rápido, as quatro ideias de HTML e CSS que explicam por quê: semântica, caixa, cascata e especificidade. O resultado está em etapas/03-html-e-css-para-relembrar.

Na entrada do parque, uma placa diz: "Proibido acampar". Lá dentro, numa clareira, outra placa diz: "Área de camping liberada". Qual vale ali? A da clareira, porque é mais específica: fala daquele lugar, e não do parque inteiro.

Se duas placas igualmente específicas disserem coisas diferentes, vale a mais recente. E se a Defesa Civil colar um aviso de interdição, ele passa por cima de todas as placas. É o !important: funciona, mas, se toda placa virar um aviso de emergência, ninguém mais entende o que vale.

Semântica: cada tag diz o que o conteúdo é

Uma página feita só de <div> pode até ficar bonita, mas não diz nada sobre si mesma. As tags semânticas dizem: <header> é o cabeçalho, <main> é o conteúdo principal (só um por página), <section> é um bloco com título, <article> é uma peça que faria sentido sozinha (como o cartão de uma trilha) e <footer> é o rodapé. Quem usa leitor de tela pula direto para o <main>; o Google entende o que é o conteúdo; e o seu código fica mais fácil de ler.

Os títulos seguem a mesma lógica: um <h1> por página, e depois <h2>, <h3>, em ordem, sem pular nível. Por isso o título do cartão virou <h3>: ele está dentro da seção "Trilhas em destaque", que é um <h2>. E repare na classe h5 que continua lá: ela deixa o título com o tamanho de um h5, sem mudar o que ele é. A tag diz o significado; a classe cuida da aparência.

Caixa: todo elemento é um retângulo

Para o CSS, todo elemento é uma caixa com quatro camadas, de dentro para fora:

margin
border
padding
conteúdo

O padding é o respiro de dentro (o card-body dá 1rem de padding ao cartão); a margem é o espaço de fora, que afasta a caixa das vizinhas. E há um detalhe que o Bootstrap muda para você. Por padrão, o width mede só o conteúdo, e o padding e a borda são somados por fora: uma caixa de width: 300px com 20px de padding acaba com 340px. O Bootstrap aplica esta regra a todos os elementos:

Com box-sizing: border-box, o width passa a incluir o padding e a borda: a caixa de 300px fica com 300px. É por isso que as colunas do grid do Bootstrap (capítulo 7) se encaixam sem sobrar nem faltar.

Cascata e especificidade: quem vence quando duas regras brigam

Quando duas regras dão valores diferentes à mesma propriedade do mesmo elemento, o navegador decide nesta ordem:

  1. Importância: uma declaração com !important passa na frente das outras.
  2. Especificidade: vence o seletor mais específico. Ela é contada em três números, (ids, classes, elementos): h3 vale (0,0,1), .titulo vale (0,1,0), .cartao .titulo vale (0,2,0) e #trilha-salto vale (1,0,0). Compara-se da esquerda para a direita: um id vence qualquer quantidade de classes. Um style="…" escrito na própria tag passa na frente de todos os seletores.
  3. Ordem: empatou em tudo? Vence a que vem depois, no mesmo arquivo ou num arquivo carregado depois.

Teste no simulador. Ligue e desligue as regras e veja qual cor o título assume, e por quê:

Trilha do Salto

  1. h4 { color: verde-mata; }
  2. .titulo { color: terra; }
  3. .titulo { color: azul; }
  4. .cartao .titulo { color: roxo; }
  5. #trilha-salto { color: vermelho; }
  6. h4 { color: verde-água !important; }
Aprofundando: e quando a regra do Bootstrap usa uma variável vazia?

A regra .card-title do Bootstrap 5.3 é color: var(--bs-card-title-color), e essa variável vem vazia. Uma cor vazia não vale, e o título acaba herdando a cor do cartão. Mesmo assim, ela tem especificidade (0,1,0) e participa da briga: é por isso que, no passo "E se eu trocar?", a sua regra perde quando vem antes.

Troque a ordem dos dois <link>, deixando o style.css antes do Bootstrap, e recarregue. O título volta a ficar escuro: agora quem vem depois é o Bootstrap. O cabeçalho e o rodapé continuam do mesmo jeito, porque o Bootstrap não tem nenhuma regra para .site-header nem para .site-footer. Só perde a regra que briga com outra.

Desfaça a troca. A regra de ouro do livro sai daqui: o seu CSS vem sempre depois do framework.

O CSS não mostra mensagem quando uma regra perde: ela simplesmente não vale. As duas causas mais comuns são o seu style.css ligado antes do Bootstrap, ou um seletor menos específico que o do framework. Inspecione o elemento: se a sua declaração aparece riscada na aba Styles, a regra que está acima dela é a que venceu. Confira a ordem dos <link> e compare as especificidades.

Com color: verde;, nada acontece: verde não é um nome de cor do CSS (que conhece green), e o navegador ignora a declaração inteira, sem erro no console. No DevTools, a declaração aparece riscada e com um ícone de aviso ao lado. Use um nome em inglês, um código como #2f5d3a ou, a partir do capítulo 6, uma variável do seu design system.

O !important resolve na hora, e cria o próximo problema: para mudar aquela propriedade de novo, só com outro !important, mais específico. Em pouco tempo, todo o CSS vira uma disputa de avisos de emergência. Antes de usar, procure o motivo de a regra estar perdendo: quase sempre é a ordem dos arquivos ou um seletor fraco demais.
Qual seletor tem a maior especificidade?

Três classes valem (0,3,0). Um id vale (1,0,0), e a comparação começa pelos ids: um id vence qualquer quantidade de classes.

Dois elementos valem (0,0,2), a menor das três.

O seu .card-title { color: ... } está certo, mas o título não muda de cor. Qual é a causa mais provável?

Qualquer cor pode ser mudada. A questão é qual regra vence a briga.

O !important até resolveria, mas esconderia a causa real e criaria o próximo problema. A solução é carregar o seu CSS depois do framework.

Com box-sizing: border-box, uma caixa com width: 300px, padding: 20px e borda de 1px ocupa quanto de largura?

340px seria sem a borda e sem o border-box. Com border-box, o padding e a borda ficam por dentro dos 300px.

342px é o resultado do box-sizing padrão (content-box), que soma o padding e a borda por fora. Com border-box, a caixa fica com os 300px.

Por que o título do cartão tem a tag h3 e a classe h5 ao mesmo tempo?

Não é erro: a classe h5 existe justamente para dar a aparência de um h5 a qualquer elemento, sem mudar o que ele é.

A classe não muda nada para o Google. Ela é só aparência; quem dá o significado é a tag.

No seu projeto, monte a estrutura semântica da página principal (header, main, seções com título e footer), com os títulos em ordem. Crie o seu css/style.css, ligado depois do framework, e use-o para mudar a cor de um elemento que o framework já estiliza.

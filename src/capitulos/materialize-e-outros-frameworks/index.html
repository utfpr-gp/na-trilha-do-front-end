O Bootstrap é o framework CSS mais usado, mas está longe de ser o único. Neste extra, a vitrine do Início do Trilheiro (o menu, o banner, os três cartões e as dicas de segurança num modal) é refeita em dois outros: o Materialize, que segue o Material Design do Google, e o Bulma, que é só CSS. Os mesmos dados, as mesmas cores do design system, três jeitos de escrever.

A comparação mostra o que muda (os nomes das classes, quem cuida do JavaScript, como se troca o tema) e o que não muda: grid, cartões, botões e menus existem em todos. E mostra uma lição de quem trabalha com ferramentas de terceiros: a documentação, o tutorial e a versão instalada nem sempre concordam. O resultado está em etapas/extra-materialize.

Toda bota de trilha tem solado, cano e cadarço. Muda o desenho, o peso, o jeito de amarrar, e cada marca chama as peças por um nome. Quem sabe o que precisa de uma bota (firmeza no tornozelo, sola que segura na pedra) troca de marca sem medo: só precisa aprender onde fica cada coisa.

Os frameworks CSS são as marcas. Grid, cartão, botão, menu e modal existem em todos. O que você aprendeu com o Bootstrap (pensar em colunas por breakpoint, montar componentes com classes, trocar o tema por variáveis) vale para qualquer um.

Materialize: uma história em duas versões

O Materialize original (materialize-css) parou na versão 1.0.0, de 2018. A comunidade continuou o projeto com outro nome, @materializecss/materialize, e a versão 2 mudou bastante coisa: o tema passou para as variáveis do Material Design 3, o menu ganhou outra marcação, e o modal virou o <dialog> do próprio navegador. A maior parte dos tutoriais na internet é da versão 1, e o código deles não funciona igual na 2.

Aprofundando: e o Pico, e os frameworks "sem classes"?

Há frameworks que vão no caminho oposto ao do Bootstrap. O Pico estiliza o HTML semântico direto: um <button> já sai bonito, um <article> vira cartão, sem nenhuma classe. É ótimo para páginas simples e protótipos, e fica limitado quando o design pede algo próprio. E há o Tailwind, que não tem componentes prontos, só classes pequenas, uma para cada propriedade (veja o extra do Tailwind).

Tire o --bulma-primary-invert-l: 100% do Bulma e recarregue: o texto do menu fica escuro sobre o verde, quase ilegível. O Bulma calcula a cor do texto a partir da luminosidade da cor primária, e o padrão dele espera uma cor clara. Desfaça.

Um <nav> sem classe, com .nav-wrapper, ganhava a cor primária no Materialize 1; no 2, sai sem fundo e com os links no azul padrão. A .modal numa <div> com M.Modal.init não abre mais. Confira a versão do tutorial e use a documentação da versão que você instalou.

A documentação do Materialize 2 mostra o botão preenchido como class="btn filled", mas o CSS da 2.4.0 só tem .btn-filled. O botão saiu cinza até isso ser conferido no próprio arquivo CSS. Quando algo não funciona, abra o CSS do framework e procure a classe.

O CSS distribuído do Materialize 2.4.0 tem uma regra quebrada para os links: uma função do Sass que não foi compilada. O navegador ignora a regra, e os links ficam no azul padrão. A correção é dar a cor no seu CSS: a { color: var(--md-sys-color-primary); }.

No CSS do Materialize 2.4, o .nav-wrapper vem depois do .primary, com a mesma especificidade, e ganha: o menu ficava claro mesmo com a classe primary. É a cascata do capítulo 3: .nav-wrapper.primary, com as duas classes, desempata.

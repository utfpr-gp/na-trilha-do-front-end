O Trilheiro ganha hoje a sua primeira peça: o cartão de uma trilha, com foto, dificuldade, nome, cidade, distância e um botão. E ele vai ser feito duas vezes.

Não dá, porque não há diferença na tela. A diferença está no código: o da esquerda precisou de um arquivo CSS de 85 linhas, escrito à mão. O da direita não tem nenhuma linha de CSS próprio, só nomes de classes no HTML. Ao fim do capítulo, você vai saber dizer o que essas classes estão fazendo por você, e quando vale a pena usá-las.

As duas versões estão na pasta etapas/01-por-que-um-framework do repositório do livro.

Para dormir no mato, você pode montar um abrigo com galhos, cordas e lona. Funciona, e fica do jeito que você quiser, mas leva tempo, e cada detalhe depende de você saber fazer.

Ou você leva uma barraca pronta: varetas numeradas, lona cortada na medida, montagem em minutos. Qualquer pessoa que já armou uma barraca daquele modelo sabe montar a sua. Em troca, ela pesa na mochila e se parece com a de metade do acampamento.

O CSS puro é o abrigo de galhos; o framework CSS é a barraca pronta. Guarde as duas palavras do fim da analogia, peso e parecido, porque elas vão voltar.

Um framework CSS como o Bootstrap é, antes de tudo, um arquivo CSS grande, já escrito. Dentro dele há centenas de regras, cada uma presa a um nome de classe combinado: .card, .card-body, .btn, .btn-primary, .badge. Você não escreve essas regras. Você escreve o HTML e aplica as classes, e as regras que já estão no arquivo fazem o resto.

Repare no que cada classe resolve sozinha: .card desenha a borda e os cantos arredondados, .card-body dá o respiro interno, .btn transforma um link num botão com espaçamento, cursor e anel de foco para quem navega pelo teclado, e .btn-primary escolhe as cores desse botão.

Agora desmarque só a .btn e deixe a .btn-primary. O link volta a ser um link comum, sem cor de botão nenhuma. Por quê? No Bootstrap 5.3, a .btn-primary não pinta nada: ela só guarda as cores em variáveis CSS, como --bs-btn-bg. Quem usa essas variáveis para desenhar o fundo, a borda e o espaçamento é a .btn. Uma classe depende da outra.

O que o framework resolve por você

  • Consistência. Todos os botões, cartões e selos usam as mesmas medidas, os mesmos cantos e as mesmas cores. No CSS puro, isso depende de você não esquecer nenhum detalhe em nenhum arquivo.
  • Componentes prontos. Cartão, botão, selo, menu, janela modal, carrossel: dezenas de peças testadas em vários navegadores.
  • Responsividade. Um sistema de grid que reorganiza a página do celular ao computador. Você vê isso no capítulo 7.
  • Acessibilidade dos componentes. Foco visível, contraste, e os componentes com JavaScript (como a janela modal) já cuidam do teclado e dos leitores de tela. Isso chega no capítulo 10.

O que você perde

  • Identidade. Sem personalização, todo site feito com Bootstrap se parece. É a barraca igual à do vizinho. O capítulo 13 resolve isso com Sass.
  • Peso. O style.css do cartão em CSS puro tem cerca de 1,3 KB. O bootstrap.min.css tem 232 KB (cerca de 30 KB comprimido na transferência), porque traz regras para tudo, inclusive para o que você não usa.
  • Um vocabulário novo. É preciso aprender os nomes das classes, e entender o que elas fazem, para não colar classes sem saber o motivo.
Aprofundando: de onde vêm os 232 KB?

O arquivo compilado do Bootstrap traz o grid, dezenas de componentes, centenas de classes utilitárias (my-2, px-3, text-center…) e as variáveis CSS dos temas claro e escuro. Na transferência, o servidor comprime o arquivo e ele cai para cerca de 30 KB. No capítulo 13, com Sass, você aprende a importar só as partes que usa.

Quando não usar um framework?

Um framework não é obrigatório. Ele costuma atrapalhar mais do que ajudar quando:

  • a página é pequena e simples, como um cartão de visita ou uma página única de evento;
  • a identidade visual é muito própria, e você passaria mais tempo desfazendo o estilo do framework do que escrevendo o seu;
  • cada kilobyte importa, como numa página que precisa abrir rápido em conexões lentas;
  • o objetivo é aprender CSS: sem entender caixa, cascata e especificidade, as classes viram mágica. Por isso o capítulo 3 revisa esses conceitos antes de o livro mergulhar no Bootstrap.

O integrity do seu <link> não confere com o arquivo, e o navegador bloqueou o CSS por segurança. Acontece quando você troca a versão no endereço (por exemplo, de 5.3.3 para 5.3.8) e esquece de trocar o integrity, ou quando um caractere do hash se perde ao copiar. Copie de novo a linha inteira da página de introdução da documentação do Bootstrap, sempre com o endereço e o hash juntos.

Um erro de digitação no endereço (bootstrp.min.css, por exemplo) faz o CDN responder com o status 404, e o cartão aparece sem estilo. O console pode ficar em branco. O sinal está na aba Network (Rede) do DevTools (F12): recarregue a página e procure a linha do arquivo CSS em vermelho, com o status 404. Confira o endereço letra por letra, ou copie-o de novo da documentação.

Com class="btn btn-primay", o botão fica com o formato, mas sem a cor, e nenhuma mensagem aparece. O CSS não avisa quando uma classe não existe: ele simplesmente não encontra nenhuma regra para ela. Inspecione o elemento no DevTools e veja, na aba Styles (Estilos), quais regras estão sendo aplicadas. Se a classe que você escreveu não aparece em nenhuma, o nome está errado.
O que é, de fato, um framework CSS como o Bootstrap?

Quem escreve o HTML continua sendo você. O framework só traz as regras de CSS prontas.

Nada é instalado no navegador de quem visita: o CSS do framework vem junto com a página, pelo <link>.

Você tirou a classe btn de um link e deixou a btn-primary. O que acontece?

No Bootstrap 5.3, a btn-primary só guarda as cores em variáveis; quem desenha o botão com elas é a btn. Teste no simulador do Por dentro.

O CSS nunca mostra erro por causa de uma classe: ele só aplica, ou não, as regras que existem.

Para que serve o atributo integrity no <link> do CDN?

O integrity não muda a velocidade. Ele é uma conferência de segurança.

A versão está no endereço (bootstrap@5.3.8). O integrity é a impressão digital daquela versão, e por isso precisa mudar junto com ela.

Em qual destes casos faz mais sentido não usar um framework CSS?

Aqui o framework brilha: muitas peças repetidas, e várias pessoas precisando manter tudo consistente.

Tabelas, botões e modais são exatamente os componentes prontos que o framework traz.

Abra o protótipo do seu projeto e escolha um componente que se repete, como um cartão, um botão ou um selo. Procure na documentação do Bootstrap o componente equivalente e monte essa peça numa página HTML, com o Bootstrap pelo CDN, do mesmo tamanho do cartão do Trilheiro. Só uma peça, sem layout ainda.

Com o PRD pronto, o Trilheiro ganha um protótipo: as 4 telas desenhadas no celular e no computador, com os botões ligados entre si, para você clicar e sentir o site antes de escrever o HTML.

Quem desenha é uma IA, o Stitch, a partir de um pedido que você escreve com o PRD aberto do lado. E o trabalho mais importante vem depois: cortar o que a IA inventou e o PRD não pede. Os pedidos usados e as decisões de corte ficam num documento, o docs/prototipo.md, na etapa etapas/05-prototipar-com-ia.

Imagine um guia que conhece cada canto da serra e, a cada bifurcação, sugere mais um desvio: uma cachoeira escondida, um mirante, uma gruta. Tudo lindo, e no fim do dia o grupo não chegou aonde queria.

A IA de protótipo é esse guia: rápida, criativa, cheia de ideias. Quem decide o trajeto é o roteiro, o seu PRD. Você ouve as sugestões, aproveita as boas e corta o resto sem dó.

Um protótipo é a planta da casa antes da obra: mostra onde fica cada coisa e como se vai de um cômodo a outro, mas ainda não tem parede de verdade. Mudar a planta custa minutos; mudar a casa pronta custa dias. Por isso ele vem antes do código.

Um bom protótipo para começar a programar tem três características:

  • Responsivo: cada tela existe no celular e no computador.
  • Navegável: os botões e links levam às outras telas, como no site de verdade.
  • Do tamanho do PRD: só as telas e os componentes que as histórias pedem.

As ferramentas

  • Stitch: uma ferramenta do Google que gera telas a partir de um texto (ou de uma imagem de inspiração). Ela monta junto um design system com as cores e as fontes, cria a versão de computador a partir da de celular e liga os botões com o recurso Instant Prototype.
  • Figma: a prancheta de design mais usada no mercado. O Stitch exporta as telas para ele, para ajustes finos à mão.
  • MCP (Model Context Protocol): uma forma de a IA do seu editor conversar com outras ferramentas. Com o MCP do Stitch, a IA do editor lê as telas do protótipo e ajuda a escrever o HTML. Ele entra em cena quando você começa a programar, a partir do capítulo 7.

Celular primeiro

Peça primeiro a versão de celular. A tela pequena obriga a escolher o essencial: o que não cabe ali, provavelmente não é tão importante. Depois, a versão de computador só redistribui o espaço que sobrou. É o mesmo caminho que o grid do Bootstrap faz, do menor para o maior, no capítulo 7.

A triagem: o passo que a IA não faz por você

A IA quase sempre devolve mais do que foi pedido. No Trilheiro, ela criou uma tela de login, um mapa interativo, estrelas em cada cartão e uma busca por texto. Cada sugestão passou por uma pergunta só: alguma história do PRD pede isso?

Cortar não é desperdício: cada tela a mais é HTML, CSS e JavaScript que você vai precisar escrever, testar e saber explicar. E a regra do livro vale aqui também: nenhum componente entra no código sem que você saiba dizer o que ele é e por que está ali.

Aprofundando: e o código que o Stitch gera?

Por trás de cada tela, o Stitch escreve HTML, e por padrão costuma usar o Tailwind CSS, um framework que pensa de um jeito diferente do Bootstrap (o capítulo "Para ir além" sobre o Tailwind explica a diferença). Neste livro, o framework é o Bootstrap: depois de escolher, peça ao Stitch para ajustar as telas aos componentes do Bootstrap 5.3. O protótipo serve para você enxergar o site; o código você escreve e entende, nos próximos capítulos.

A IA criou login, painel, perfil e configurações, e agora parece que tudo isso precisa ser feito. Não precisa. Volte ao PRD: o que nenhuma história pede sai do protótipo e vai para "Fora do escopo". O protótipo serve ao projeto, e não o contrário.

Classes como bg-green-700, rounded-lg e, principalmente, as que têm dois-pontos, como md:grid-cols-3, são do Tailwind, e não do Bootstrap. Não copie esse código para o projeto. Peça ao Stitch para ajustar as telas aos componentes do Bootstrap 5.3, e escreva o HTML seguindo os capítulos 7 a 10.

Deixar para depois faz a tela parecer parte do projeto. A triagem é justamente o momento de decidir.

Por que começar o protótipo pela versão de celular?

O Stitch gera as duas versões. Começar pelo celular é uma escolha de projeto.

Muita gente usa computador. Celular primeiro é sobre prioridade, e não sobre deixar o computador de lado.

Qual pedido de MCP segue a regra do livro?

Gerar tudo de uma vez traz componentes e classes que você não sabe explicar. Uma peça de cada vez.

"O que achar melhor" deixa a IA decidir o escopo e o framework. Nomeie a peça e o componente.

O código de uma tela tem md:grid-cols-3. O que isso indica?

O Bootstrap escreve as colunas como col-md-4, com hífen. Os dois-pontos são marca do Tailwind.

Não é erro: é a sintaxe do Tailwind, que o Stitch costuma usar por padrão.

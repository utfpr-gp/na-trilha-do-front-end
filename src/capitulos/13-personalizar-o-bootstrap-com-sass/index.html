Desde o capítulo 1, o botão "Ver trilha" é azul, o azul do Bootstrap. No capítulo 6, os tokens mudaram o cabeçalho e os títulos, mas não alcançaram os componentes. Hoje isso acaba: o Bootstrap passa a ser compilado com o tema do Trilheiro, e todos os botões, links e componentes saem verde-mata e terra, inclusive os tons de quando o mouse passa por cima, que o Bootstrap calcula sozinho.

A ferramenta é o Sass, e a mudança cabe em poucas linhas. O resultado está em etapas/13-personalizar-o-bootstrap-com-sass.

Lembra da barraca pronta do capítulo 1, igual à de metade do acampamento? Dá para pintá-la depois, peça por peça, e sempre sobra um canto da cor antiga. Ou dá para encomendá-la já na cor certa: a fábrica usa a mesma forma e as mesmas peças, só troca o tecido antes de costurar.

Pintar depois é escrever CSS com !important por cima do Bootstrap. Encomendar na cor certa é mudar as variáveis do Bootstrap antes de ele ser gerado, com Sass.

O Sass é uma versão ampliada do CSS, com variáveis (que começam com $), arquivos parciais, funções e mixins. O navegador não entende Sass: um compilador transforma o seu .scss num .css comum. Há dois momentos, e não convém misturá-los:

  3. No navegadorChega só o .css, com os valores já decididos. A cascata do capítulo 3 age aqui.

O segredo: o !default

Dentro dos arquivos do Bootstrap, as variáveis são escritas assim: $primary: $blue !default;. O !default quer dizer "use o azul só se ninguém escolheu uma cor antes". No Sass, sem nada de especial, o último valor vence, como no CSS. O !default é o Bootstrap abrindo mão de propósito:

Daí a regra que este capítulo inteiro ensina, e que você vai repetir muitas vezes:

  • Variáveis do tema: antes do Bootstrap. O !default respeita quem chegou primeiro.
  • Regras de CSS próprias: depois do Bootstrap. A cascata dá razão a quem chega por último.

E o !important?

Ele parece parente do !default, mas é de outro mundo. O !default é do Sass, age sobre uma variável, na compilação, e some do CSS final: ele cede. O !important é do CSS, age sobre uma propriedade, no navegador, e vai junto no CSS final: ele força. Para trocar a cor primária, um .btn-primary { background: … !important; } troca um lugar; a variável $primary troca todos os lugares de uma vez: botões, links, fundos, bordas, o contorno do campo selecionado, os tons de hover.

O que dá para mudar por variável

Cores do tema ($primary, $secondary, $success…), o fundo e o texto da página ($body-bg, $body-color), as fontes ($font-family-sans-serif, $headings-font-family), os cantos ($border-radius) e centenas de outras. A lista completa fica no arquivo node_modules/bootstrap/scss/_variables.scss. O que não tem variável, como o layout de uma seção sua, continua no seu CSS, depois do Bootstrap.

O --save-dev anota o Sass em devDependencies: ele é uma ferramenta de quem desenvolve, e quem visita o site nunca baixa. Se preferir uma extensão, a Live Sass Compiler (de Glenn Marks), do VS Code, faz o mesmo trabalho.

O caminho do @import está errado (aqui, "bootstap", sem o "r"), ou faltou o --load-path=node_modules no comando, ou o npm install não foi feito. O Sass aponta a linha e a coluna: 2:9. Erros de verdade começam com Error: e não geram o CSS.

Avisos não são erros: o CSS foi gerado. O Sass avisa que o @import vai deixar de existir numa versão futura, mas o Bootstrap 5.3 ainda é escrito com ele. Sem as opções do script, aparecem 20 avisos e a linha "WARNING: 311 repetitive deprecation warnings omitted.". O --quiet-deps e o --silence-deprecation=import deixam a saída limpa, para que um erro de verdade não se perca no meio deles.

A tag da documentação do Bootstrap traz integrity e crossorigin, o lacre do arquivo do CDN (capítulo 1). No seu main.css, o lacre não confere, e o navegador se recusa a carregar o CSS. Use a tag limpa: <link rel="stylesheet" href="css/main.css">.
Onde vão as variáveis do tema no main.scss?

Depois é tarde: o Bootstrap já foi gerado com os valores dele. O !default só respeita quem chegou antes.

As variáveis do Sass só existem na compilação. Elas precisam estar no .scss, antes do Bootstrap.

O que o !default significa em $primary: $blue !default;?

Ao contrário: o !default cede. Ele só vale se a variável ainda não tem valor.

O !important força, no navegador. O !default cede, na compilação, e nem aparece no CSS final.

Por que mudar $primary é melhor que .btn-primary { background: … !important; }?

A vantagem não é velocidade: é trocar todos os lugares de uma vez, sem caçar regra por regra.

O !important funciona, mas troca um lugar só, e obriga a escrever outro !important para cada mudança futura.

Apareceu DEPRECATION WARNING [import] ao compilar. O que fazer?

O aviso só diz que o @import vai mudar no futuro. O Bootstrap 5.3 ainda usa @import.

O <link> é do HTML. O @import do Sass junta os arquivos na compilação.

No seu projeto, instale o Sass, crie o scss/main.scss com as cores e as fontes do seu design system antes do @import do framework, crie os scripts de compilar e troque o CSS original do framework pelo seu css/main.css.

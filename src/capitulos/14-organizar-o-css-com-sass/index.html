O style.css do Trilheiro cresceu capítulo a capítulo, e hoje mistura navbar, faixa de destaque, cartões, etiquetas e rodapé num arquivo só. Ele deixa de existir: cada parte da página vira um arquivo Sass próprio, as cores viram variáveis, os espaços seguem uma função, a regra das fotos vira um mixin, e os três selos de dificuldade passam a ser gerados por um laço a partir de um mapa.

Na tela, nada muda. No código, cada coisa passa a ter um endereço. O resultado está em etapas/14-organizar-o-css-com-sass.

Numa mochila sem divisões, a lanterna some embaixo do casaco, e você esvazia tudo para achá-la. Numa mochila com compartimentos, o kit de primeiros socorros fica sempre no mesmo bolso, e qualquer pessoa do grupo sabe onde procurar.

Os parciais do Sass são os compartimentos: o rodapé no _footer.scss, os cartões no _cards.scss. E as variáveis, as funções e os mixins são os itens que você leva uma vez só e usa em vários lugares, em vez de carregar duas lanternas.

Parciais e @use

Um parcial é um arquivo Sass com nome começando por _ (_footer.scss): o compilador não gera um CSS para ele sozinho; ele só existe para ser chamado por outro arquivo. Para usar o que está num parcial, o arquivo chama @use, e o que vem de lá é usado com o nome do arquivo (ou um apelido) na frente:

A regra que evita a maioria dos erros: cada arquivo só enxerga o que ele mesmo chamou. Se o _footer.scss usa uma cor dos tokens, é ele que precisa do @use "tokens".

Aprofundando: variável do Sass ou variável CSS?

A variável do Sass ($verde-mata) é resolvida na compilação: no CSS final só sobra o valor. A variável CSS (--cor-marca, do capítulo 6) chega até o navegador e pode mudar com a página aberta, por exemplo num modo escuro. Para alimentar o Bootstrap, só as do Sass servem; para trocar valores ao vivo, as do CSS.

Tire o @use "tokens" as t; do topo do _footer.scss e compile: o Sass para com um erro, porque o rodapé deixou de enxergar as cores. Devolva. Agora acrescente facil-com-guia: #1f5f99 ao mapa $dificuldades e compile: aparece a classe .badge-facil-com-guia no CSS, sem você escrever nenhuma regra. Apague a linha.

O arquivo usa $verde-mata, mas não chamou o parcial onde ela está. Ponha @use "tokens" as t; no topo e escreva t.$verde-mata. Chamar os tokens no main.scss não os torna visíveis nos outros arquivos.

O arquivo chamou @use "tokens"; (sem apelido) e escreveu t.$verde-mata. Sem o as t, o nome a usar é o do arquivo: tokens.$verde-mata. Ou acrescente o apelido: @use "tokens" as t;.

Com @include m.cover-image(4 / 3), o Sass entende uma divisão, e não a barra do aspect-ratio. O mixin do Trilheiro recebe a largura e a altura separadas e escreve a barra com interpolação: aspect-ratio: #{$largura} / #{$altura};. Assim, no CSS final, sai 4/3, como deve.
Para que serve o _ no começo de _footer.scss?

O Git não liga para o sublinhado. Quem liga é o compilador do Sass.

A ordem é decidida pelo main.scss. O sublinhado só marca o arquivo como parcial.

Qual a diferença entre uma função e um mixin?

São diferentes: uma devolve um valor, a outra um bloco de propriedades.

Nenhuma das duas gera classes sozinha. Quem gerou as classes dos selos foi o @each.

Dentro de .site-footer { … }, o que vira &__aviso?

O & cola o texto no seletor de fora, sem espaço.

O & é do Sass e some na compilação, trocado pelo seletor de fora.

O Sass diz Undefined variable no _footer.scss, mas a variável existe no _tokens.scss. Por quê?

Com @use, a ordem no main.scss não resolve: o arquivo que usa a variável precisa chamá-la.

Funcionam, desde que o arquivo chame o parcial onde a variável está.

No seu projeto, divida o seu CSS próprio em parciais Sass, uma parte da página por arquivo, com os tokens num parcial de variáveis. Use pelo menos uma função, um mixin e um aninhamento de verdade (onde eles evitam repetição), e compile tudo junto com o framework.

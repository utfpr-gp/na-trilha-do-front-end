Nos frameworks dos capítulos anteriores, um cartão é uma peça pronta: você escreve class="card" e recebe borda, sombra e espaçamento. O Tailwind, um dos nomes mais comentados do front-end hoje, não tem cartão. Tem só classes pequenas, cada uma com uma propriedade: rounded-lg arredonda, shadow-sm põe a sombra, p-5 dá o espaço. O cartão você monta, classe por classe, direto no HTML.

Neste extra, a vitrine do Início do Trilheiro é refeita em Tailwind 4, com as cores e as fontes do design system virando o tema dele. No fim, o CSS da página inteira tem 10,7 KB, porque o Tailwind gera só as classes que o HTML usa. O resultado está em etapas/extra-tailwind.

Num parque, dá para alugar um abrigo pronto: chega montado, do jeito que o fabricante desenhou. Ou dá para levar um kit de peças padronizadas (estacas, lonas, cordas de tamanhos fixos) e montar o abrigo do seu jeito, peça por peça. Dá mais trabalho no começo e mais liberdade depois.

O Bootstrap é o abrigo pronto: componentes com a cara dele, que você personaliza. O Tailwind é o kit: peças pequenas e padronizadas, as classes utilitárias, que você combina para chegar exatamente ao seu design. Você já usou peças assim nos utilitários do Bootstrap (capítulo 8), como o mb-3. O Tailwind faz a página inteira assim.

O mesmo cartão, dois jeitos

No Tailwind, cada classe é uma decisão visível: flex flex-col empilha, overflow-hidden rounded-lg arredonda os cantos da foto junto com o cartão, aspect-4/3 object-cover é o mixin de foto do capítulo 14, text-verde-mata é a cor do título. Muita classe, e nenhum arquivo de CSS para abrir.

Os breakpoints viram prefixos, como no Bootstrap. A grade de cartões é uma linha só:

Uma coluna no celular, duas a partir do sm, três a partir do lg, com o display: grid do capítulo 11 por baixo.

O tema: o design system vira classes

No Tailwind 4, o tema é CSS. Cada variável do @theme gera uma família de classes: --color-verde-mata cria bg-verde-mata, text-verde-mata, border-verde-mata, e assim por diante.

Só o que é usado

O Tailwind lê os seus arquivos procurando nomes de classe e gera o CSS só com eles. A página do Trilheiro inteira ficou com 10,7 KB de CSS, contra os 30 KB (comprimidos) do Bootstrap completo. O preço: o nome da classe precisa aparecer inteiro em algum arquivo, como texto.

Aprofundando: utilitário ou componente, qual é melhor?

Nenhum dos dois, em geral. O Tailwind brilha quando o design é próprio e cheio de detalhes, e quando a equipe trabalha com componentes de JavaScript (Angular, React, Vue): o "cartão" vira um componente, e as classes ficam escritas num lugar só. O Bootstrap brilha quando os componentes prontos bastam e o tempo é curto, e quando é preciso JavaScript pronto para modal, carrossel e menu, que o Tailwind não tem. Muitos projetos misturam as ideias: o próprio Trilheiro usa componentes do Bootstrap e utilitários como d-flex e mb-3.

Troque bg-moderada por bg-moderado, que não existe no tema, e rode npm run css. Nenhum erro: o Tailwind só não gera a classe, e o selo fica sem fundo, com o texto branco invisível sobre o branco. Desfaça.

O Tailwind lê os arquivos como texto e procura nomes inteiros. Um nome montado na hora, como `bg-${trail.dificuldade}`, nunca aparece inteiro, e a classe não é gerada (foi conferido: só a classe escrita por inteiro foi para o CSS). Escreva os nomes completos, num objeto, por exemplo: { facil: 'bg-facil', moderada: 'bg-moderada', dificil: 'bg-dificil' }.

Um bg-verde-mta simplesmente não gera nada, sem aviso. A extensão Tailwind CSS IntelliSense, do VS Code, completa os nomes e mostra o CSS de cada classe ao passar o mouse.

O Tailwind 4 mudou a configuração: o tema saiu do tailwind.config.js e foi para o @theme no CSS, e o @tailwind base; @tailwind components; virou um @import "tailwindcss";. Muitos exemplos na internet ainda são da versão 3. Confira a versão antes de copiar.

Vinte classes num elemento, repetidas em três cartões, é difícil de manter: mudar a sombra é mudar em três lugares. Num site de HTML puro, como o Trilheiro, monte o elemento repetido pelo JavaScript (como o createTrailCard do capítulo 19), para as classes ficarem num lugar só.
O que é uma classe utilitária?

O .card junta várias propriedades num componente. A utilitária faz uma coisa só.

As utilitárias são só CSS.

Por que o CSS do Tailwind do Trilheiro ficou com 10,7 KB?

Ele tem milhares de classes possíveis. Só as usadas vão para o arquivo final.

Não há nada no CDN: o CSS gerado é tudo o que a página usa.

O que sm:grid-cols-2 lg:grid-cols-3 faz?

O prefixo vale a partir do breakpoint, como no Bootstrap. No celular, sem prefixo, a grade tem uma coluna.

Três só a partir do lg.

Como as cores do Trilheiro viraram classes do Tailwind?

O Tailwind gera as classes a partir do tema: --color-verde-mata vira bg-verde-mata, text-verde-mata…

Dá, e é o jeito recomendado: o design system vira o tema.

Até aqui, as trilhas moravam num arquivo JavaScript, e o formulário de cadastro conferia tudo, mas não gravava nada. Hoje o Trilheiro ganha um servidor: o json-server, que transforma um arquivo db.json numa API de verdade, rodando no seu computador. As páginas passam a pedir os dados pela rede, com o fetch, e a esperar a resposta.

Muda muita coisa de uma vez: o Início e a tela Trilhas buscam as trilhas no servidor, com um aviso de "Carregando" e uma mensagem se algo falhar; a página da trilha deixa de ser sempre a do Salto e mostra a trilha do endereço (trilha.html?id=3), com as fotos, o guia e os relatos dela; o cadastro grava a trilha nova e leva ao detalhe dela; e o modal "Conte como foi" publica um relato. O resultado está em etapas/23-fetch-e-json-server.

Na trilha, você pede pelo rádio: "Base, qual a previsão para amanhã?". A resposta não vem na hora: a base precisa consultar, e a ligação pode cair. Enquanto espera, você não fica parado; segue arrumando a mochila. Quando a resposta chega, você a usa. E se ninguém responde, você precisa de um plano B.

O fetch é o rádio: manda o pedido para um endereço e devolve uma promessa de resposta. O await é o "fico esperando esta resposta", sem travar o resto da página. E o try/catch é o plano B para quando a base não responde.

Uma API REST no seu computador

O json-server lê o db.json e cria uma API REST: cada lista do arquivo vira um endereço, e o método do pedido diz o que fazer:

  • GET /trilhas: todas as trilhas;
  • GET /trilhas/3: a trilha de id 3 (ou 404, se não existir);
  • GET /trilhas/3?_embed=relatos: a trilha, com os relatos dela dentro, num campo relatos;
  • POST /trilhas: grava uma trilha nova e responde com ela, já com o id que o servidor gerou (status 201);
  • POST /relatos: grava um relato.

O relato sabe de que trilha é pelo campo trilhaId, o nome que o json-server espera para ligar as duas listas. Os dados são gravados de volta no db.json: pare e rode o servidor de novo, e eles continuam lá.

fetch, async e await

Pedir dados pela rede leva tempo, e o JavaScript não fica parado esperando. O fetch devolve na hora uma Promise, uma promessa de resposta. Dentro de uma função async, o await pausa só aquela função até a promessa se cumprir:

Até aqui, cada cartão de trilha estava escrito à mão no HTML, e a mesma trilha aparecia copiada no Início e na tela Trilhas. Hoje os dados saem do HTML: as trilhas viram uma lista de objetos num arquivo JavaScript, e os cartões passam a ser montados pelo código, todos do mesmo molde. O Início mostra só as trilhas em destaque; a tela Trilhas, todas, inclusive uma quarta, a Escadaria do Salto, que ainda não tem foto e ganha a imagem padrão.

De quebra, a distância passa a aparecer com vírgula ("4,5 km"), o coração do Início começa a funcionar, e o código se organiza em arquivos pequenos, cada um com uma tarefa, ligados por módulos. O resultado está em etapas/19-objetos-arrays-e-classes.

Um centro de visitantes guarda um registro de cada trilha, sempre com os mesmos campos: nome, cidade, distância, dificuldade. Os registros ficam num caderno, em ordem. Para montar o mural, ninguém desenha cada cartaz do zero: um carimbo faz o cartaz e só os dados mudam.

O objeto é o registro; o array, o caderno; a classe é o modelo do registro, que diz que campos ele tem e o que se sabe fazer com eles. E a função que monta o cartão é o carimbo. Para mudar uma trilha, você mexe no registro, e o mural se ajeita sozinho.

O arquivo usa import, mas entrou na página com um <script src="…"> comum. Acrescente type="module". Só o arquivo de entrada vai no HTML; os importados, não.

Com o endereço começando em file://, o navegador não carrega módulos, e a página fica sem nenhum cartão. Abra pelo Live Server (http://127.0.0.1:5500).

O nome entre chaves precisa ser igual ao do export, com as mesmas maiúsculas. Confira também se a função tem o export na frente, e se o caminho do import tem o ./ e o .js.

Uma classe não é chamada como função: new Trail(data), e não Trail(data).

O filter (e o map) devolve um array novo e deixa o original como estava. trails.filter(…) sozinho numa linha não faz nada: guarde o resultado numa variável, ou use-o direto, como em render.
O que trails.map((trail) => trail.nome) devolve, para quatro trilhas?

O map transforma cada item, e devolve um array do mesmo tamanho.

Escolher itens é com o filter. O map transforma cada um.

E trails.find((trail) => trail.id === '9'), se não há trilha com o id 9?

O array vazio é o que o filter devolve. O find devolve um item, ou undefined.

Não achar não é erro: o find devolve undefined, e o seu código decide o que fazer.

Para que serve o constructor da classe Trail?

Quem monta o cartão é o createTrailCard. A classe só cuida dos dados da trilha.

Quem exporta é a palavra export antes de class.

Por que os dados entram no cartão por textContent, e não dentro do template string?

Aceitam, sim. O problema é que, com innerHTML, o que vem nos dados vira HTML.

A razão é a segurança (XSS, capítulo 18), que importa quando as trilhas vierem de um cadastro.
